# Repository governance

The canonical catalogue is the source of truth for planned product keys and tier order. A planned record is inventory, not implementation or release evidence.

- Changes to catalogue keys, manifest schemas, release gates or workflows require review by the repository owner.
- Product workspaces must be admitted through reviewed catalogue metadata, a manifest and CI coverage.
- Launch kits compose versioned products and require composition validation; they must not duplicate product source.
- Product rights, dependency licences, security, accessibility and release evidence are explicit gates.
- The repository does not authorize the marketplace to publish products, alter prices, issue refunds, grant entitlements or release funds.
- Tinlance Agent System remains the authority for governed agent execution, identity, authorization, policy, approvals, runtime, tools, secrets, audit and evidence.

Do not treat this document as evidence of branch protection or required-review settings. Those are GitHub repository settings and must be verified separately.
